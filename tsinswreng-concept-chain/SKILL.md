## 先看示例

場景：你在寫一份「C#函數式編程入門筆記」，要講清楚純函數。

按概念鏈登記後是這樣:

```typst
// 由文檔所有者定義，勿動
#let MkR(display, descr) = (
	
)

#let Rf(reg) = {}
#let RfRaw(name)={}

// ── 概念鏈：登記順序 = 閱讀順序 ──

#let 全局變量 = Mkr[全局變量][ //建議把變量名和display參數 保持一致。這樣在正文中引用的時候 看上去會比較自然
	全局變量（global variable） 是指在函數外部、最外層作用域宣告的變量，通常整個程式、模組或檔案都能存取，生命週期從宣告開始，一直到程式或模組結束。

	簡單說：它不是某個函數的局部變量，而是大家都可以看到、可能都可以改的變量。
]

#let 副作用 = Mkr[副作用][
	副作用（side effect） 是指：一個函數或表達式在執行時，除了「計算並回傳結果」之外，還對外部世界或程式狀態造成了可觀察的改變，或與外界發生了互動。

	簡單說：函數不只回傳值，還「順便」做了別的事。

	常見的副作用:
	- 修改#Rf(全局變量)或靜態變數
	- 修改傳入的物件、陣列、參數
	- 印出內容、寫 log
	- 讀寫檔案、資料庫
	- 發送網路請求
	- 修改 UI
	- 修改環境變數、系統狀態
	- 拋出異常、改變控制流
	- 依賴外部可變狀態，例如讀取當前時間、隨機數、全域設定  
		（嚴格說這叫「外部依賴」而不是修改，但通常和副作用一起討論，因為它會讓函數不純。）

]

#let 純函數 = MkR[純函數][
	純函數（pure function） 是函數式編程中的核心概念，簡單說就是：相同輸入永遠得到相同輸出，而且不產生任何副作用。

	一個函數要稱為純函數，通常要滿足兩個條件：

	確定性：只要輸入相同，回傳結果永遠相同。
	例如 add(2, 3) 永遠回傳 5。

	無#Rf(副作用)：函數執行時，不修改外部狀態、不影響外界、也不依賴外部可變狀態。
	副作用包括：修改全域變數、修改傳入的物件/陣列、印出東西、寫檔案、發網路請求、讀取當前時間、使用隨機數等。
]

//以下是正文
C\#的`[Pure]`特性(`System.Diagnostics.Contracts.PureAttribute`)是用于標記#Rf(純函數)的特性。
```

## 體系結構

- 登記：`#let 概念變量 = MkR[顯示名稱][詳解內容]`。
- 引用：正文在**提及處**寫 `#Rf(概念變量)`——跟着名詞走，不是在段落末尾掛一行「詳見某某」
- 登記區與正文在同一文件內；`MkR` / `Rf` 是慣例名

## 概念鏈規約

登記順序 = 閱讀順序：

- 基礎概念在前、組合概念在後
- 每條只引用排在它前面的條目, **儘量避免引用未定義或後定義的條目**。 讀者從上往下走, 點任何一個引用, 跳到的條目裏儘量不應再出現沒講過的東西。 如實在需要引用未定義或後文纔定義的條目 則用`#RfRaw[未定義或後文纔定義的條目]`
- 新概念插進鏈裏邏輯合適的位置, 不是無腦尾部追加

## 在已有文檔中新增概念條目的流程

分兩步:

1. 新增條目:
   - 在合適的位置插入。自己找準位置。不一定是在開頭或末尾
2. 替換引用:
   - 把原來的裸文字引用處 都換成`#Rf`寫法的引用。這一步要看仔細來 找準換準 不要漏

## 驗證

`typst compile`可驗證；引用的變量必須已登記（漏登記、改名不同步都會在編譯時暴露）
